# 0.5.0 — A BOM describes one agent, and OpenACA knows three of them

Before this release an Agent BOM described a *place*: `scan endpoint` resolved
one config directory and `scan repo` walked one tree, each emitting one document
whose subject was that place. "Which agent is affected by this vulnerable MCP
server?" was unanswerable — the document could only say *this place has it*.

Now a BOM describes one **agent**: one runtime plus the composed context it
loads. A scan emits as many documents as agents it discovers — and this release
also grows what can be discovered, from Claude Code alone to Claude Code, Cursor
and Codex. On top of that, OpenACA gains a second output besides findings: a
compiled, host-enforceable restrictive policy for an endpoint.

Design: `docs/specs/multi-agent-support.md`, `docs/specs/cursor-agent-kind.md`,
`docs/specs/codex-agent-kind.md`, `docs/specs/policy-compiler.md`,
`docs/specs/collector-agent-rooted-uploads.md`.

## Highlights

- **The agent is `metadata.component`.** Its `bom-ref` is `root/<kind>`, its
  `name` is the runtime's display name, and it carries `openaca:agent_kind`,
  `openaca:composition_source` (`installed` or `declared`, always explicit), and
  `openaca:composition_coverage`. BOM schema version is `0.5` (ADR-0044,
  ADR-0045, ADR-0047).

- **Cursor and Codex are agent kinds.** `cursor` (plan 042, ADR-0052) and
  `codex` (plan 043, ADR-0055) join `claude-code`, each discovering its own
  installed and declared surfaces — Codex including TOML `config.toml` and
  `agents/*.toml`, and the shared `.agents/skills` directory (ADR-0058).
  Discovery finds every installed kind by default; `--kind` alone narrows to
  one kind. A root override is a per-kind capability: Claude Code and Codex
  accept `--config-dir` alongside `--kind` to relocate their root, but Cursor
  still reads parts of its composition from the home directory even once a
  root is named, so `--config-dir` alongside `--kind cursor` is rejected
  (ADR-0054, ADR-0056).

- **`openaca policy` compiles a restrictive endpoint policy.** A new top-level
  command with `validate` (check a policy document) and `compile` (scan one
  endpoint and render its host-managed policy artifact). Compilation is
  source-based and fails closed: an incomplete or malformed inventory refuses to
  compile rather than emitting a policy that silently admits what it could not
  see (ADR-0048, ADR-0049; `docs/specs/policy-compiler.md`).

- **`openaca remote policy` compiles against fresh endpoint evidence.** The
  organization policy is fetched and compiled from a scan of the endpoint at
  hand rather than from cached inventory (ADR-0061, plan 044).

- **Policy evaluation is on the `openaca.core` facade.** `Policy`, `Decision`,
  `EndpointComponent`, `parse_policy`, `parse_policy_source`,
  `evaluate_admission`, `apply_risk_gates` and the two error types are exported
  from `openaca.core`, so consumers no longer reimplement admission semantics or
  reach into `tools.*` (ADR-0062, ADR-0028). Source parsing is duplicate-key
  aware — a policy document with a repeated key is rejected, not silently
  last-wins.

- **The remote collector is agent-rooted.** A sync registers one asset — the
  machine — and sends one upload per discovered agent; the agent is named inside
  the document's `metadata.component`, so the upload envelope is unchanged. An
  agent whose upload fails is written to the pending cache and retried while the
  other agents' uploads stand (ADR-0050, plan 041). Upload redaction now covers
  BOM metadata (ADR-0051).

- **Coverage is a per-scan verdict.** `openaca:composition_coverage` states how
  much of an agent's composition the scan could observe, resolved per
  composition source as `min(baseline, evidence)` — so a manifest that failed to
  parse downgrades `complete` to `partial` instead of a scan that skipped a file
  still claiming completeness (ADR-0046). Graph warnings propagate into it.

- **`scan repo` and `bom repo` are agent-rooted too.** A repo scan discovers the
  agents a tree *declares* and emits one document each with
  `composition_source: declared`. A tree declaring no agent — a repository of
  ordinary package manifests — emits nothing and exits `0`. Evidence is a file
  the runtime owns; an empty `.claude/` directory is not evidence, and neither
  is a bare `mcp.json`, which no runtime owns exclusively.

- **Findings carry their agent.** The findings list stays flat — one SARIF path,
  one exit code, one `sarif-path` output, so the reference Action is unchanged —
  but every advisory, posture, and observation row now says which agent it
  belongs to, and each finding's composition lineage resolves against that
  agent's own graph. Text output prints one card per agent; `--format json`
  emits one document with a new `agents[]` array, so an installed agent with
  nothing configured still appears.

- **An installed runtime with no configuration is a real agent.** It is reported
  with zero components rather than being invisible — the deliberate asymmetry
  with a repo declaration.

- **Default scan output surfaces overlay taxonomies**, and an orphaned plugin
  cache is now reported rather than silently trusted (ADR-0060).

- **Bug fixes.** BOM diff pairing and manifest recovery across legacy graph and
  flat documents, empty BOM snapshots, legacy-graph/flat `bom-ref` collisions,
  pre-push hook exit-status and pushed-commit validation, and a long hardening
  pass over Cursor and Codex parsing that rejects malformed manifests, hooks,
  MCP tables and plugin registrations instead of coercing them.

## Install

`uv tool install openaca==0.5.0` or `pip install openaca==0.5.0`.

## Compatibility

Pre-V0 — no back-compat hedging.

- **Every `bom-ref` in the installed path is renamed once.** Node-key root
  labels name the kind that owns the config root, so `endpoint/<rel>` becomes
  `claude-code/<rel>`. Diffs match on `bom-ref`, so the first `openaca bom diff`
  after upgrading reports every component removed and re-added, and earlier diff
  history is not comparable across this boundary. No data is lost. There is
  deliberately no version-aware diff shim: it would be migration code to carry
  and later retire, to suppress a one-time event that is noisy rather than
  harmful. Repo-path component `bom-ref`s are unchanged.

- **Uploads change shape too.** The collector migrated with the local path: an
  uploaded BOM is rooted at `root/<kind>` and writes no `openaca:target` /
  `openaca:target_type`, where a `0.4` upload was rooted at `openaca:target`.
  Locally emitted and uploaded `bom-ref`s now agree.

- **`bom endpoint`/`bom repo` default to NDJSON on stdout** — one CycloneDX
  document per line. A single agent is a single line, so `jq` and `json.load`
  keep working, but the output is compact rather than indented. Use
  `--output-dir <dir>` for one file per agent; `--output` is deprecated and
  errors with a pointer to `--output-dir` only when more than one agent
  resolves. `scan bom --input` accepts either shape.

- **Three properties stop being written**: `openaca:target_type`,
  `openaca:agent_host`, and `openaca:runtime_hosts`. All three are still *read*
  from stored `0.4` documents — removing a property means stopping the write,
  not the read. A component's "active in" now comes from the agent that scanned
  it rather than from the parser that read the file, which is a stronger and
  correct claim: one consequence is that a VS Code `servers` block, previously
  rendered with an empty `active_in`, now names the scanning agent.

- **`scan repo` text output** gains a `coverage` row in its Target block, and
  its `host surface` reads the discovered agent's name rather than `repository`.

- **`policy compile` scopes to user-level config when `--project` is
  omitted.** `--project` is optional, matching `scan endpoint` (ADR-0017):
  passing it also scans project-local skills, MCPs, and plugin manifests.
  Without it, a component that exists solely in project-local config is
  absent from admission and risk-gate evaluation, and compilation prints a
  reminder note rather than failing.
