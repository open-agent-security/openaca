# 0.15.0 — Pi and OpenCode agent kinds

OpenACA now builds an Agent BOM for two more agent kinds, `pi` and `opencode`.
An MCP launch line held in `command` now resolves to its package.

## Highlights

- **Pi** (`pi`). OpenACA reads Pi's agent directory at `$PI_CODING_AGENT_DIR`,
  else `~/.pi/agent`, and a project's `.pi/` folder (ADR-0081). The BOM lists
  the MCP servers in `mcp.json`, the packages in the settings with their
  installed npm versions, extensions, skills and prompt templates. An extension
  and a package are each a `plugin`, so plugin admission acts on them
  (ADR-0082). The installed project layer follows Pi's `trust.json`. The kind
  is `partial` at both sources, because an extension can add MCP servers and
  skill paths at run time. `docs/specs/pi-agent-kind.md` gives the design.
- **OpenCode** (`opencode`). OpenACA reads OpenCode's configuration at
  `$XDG_CONFIG_HOME/opencode`, else `~/.config/opencode`, and a project's
  `opencode.json` (ADR-0083). MCP servers merge by name as OpenCode merges them,
  and each server states `enabled`. An npm plugin is `plugin/npm/<name>`, with
  the version of its install in OpenCode's cache (ADR-0084). OpenCode's
  `permission` settings feed no posture rule, because OpenCode allows every
  tool by default (ADR-0085). The kind is `partial` at both sources.
  `docs/specs/opencode-agent-kind.md` gives the design.
- **An MCP launch line in `command` resolves to its package.** Cursor accepts
  a whole launch line in `command` with no `args`, such as
  `"npx -y chrome-devtools-mcp@latest"`. The parser now reads the package from
  that line. Before, it treated the whole line as one executable.
- **Bug fixes.** An uppercase 40-hex commit pin on a Devin plugin is now an
  immutable version, as it already was for an MCP server. Several parsers now
  share one helper each for the plugin-key split, hooks files, npm launches,
  settings scopes, bom-refs, the overlay schema and the gitignore walk. Their
  results do not change.

## Install

`uv tool install openaca==0.15.0` or `pip install openaca==0.15.0`.

## Compatibility

Pre-V0 — no back-compatibility hedging.

- **Two new agent kinds.** `collect_installed_agents` and the declared scan can
  now return `pi` and `opencode` agents. A consumer with a closed list of kinds
  must add them. `POLICY_EVIDENCE_AGENT_KINDS` does not include them, so policy
  compilation does not read their evidence yet.
- **A Cursor MCP server with its launch line in `command` gets a new identity.**
  It is now the package that the line runs, not the whole line as an
  executable. A consumer that stored the old identity sees a new component.
- **`openaca:schema_version` stays `0.7`.** The BOM document shape did not
  change. The new kinds use the existing component types and properties.
- **The overlay record schema is unchanged.**
