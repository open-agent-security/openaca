# ADR Index

Architecture Decision Records for OpenACA. The index is loaded into every
session by a hook; full ADRs are read on-demand when an entry looks
related to the work at hand.

**When to read full ADRs:** before changing logic in the area an ADR
covers. Each entry's one-liner is a hook — if it sounds at all
adjacent to your task, click through.

**When to write a new ADR:** when you make a decision where the
rejected alternative is *plausible* and *likely to be re-suggested*,
and the reason isn't obvious from the code. See `TEMPLATE.md`.

**Supersession discipline:** ADRs are immutable once accepted. If a
later decision contradicts an existing ADR, write a NEW ADR with
`supersedes: NNNN` in its frontmatter, and update the old ADR's
frontmatter to `status: superseded` + `superseded-by: NNNN`. Never
edit an accepted ADR's body in place — old PRs need to be readable
against the rules in effect at the time.

- [ADR-0039 — Resolve MCP-server launch targets to their dependency manifests](0039-mcp-launch-dependency-resolution.md): un-defers a scoped slice of ADR-0037's declaration-based attribution — `mcp_server` is no longer a leaf. - [ADR-0041 — Model agent-component capabilities as first-class descriptors, extracted defensibly](0041-agent-component-capabilities.md): capabilities (`file_read`/`file_write`/`shell_exec`/`network_egress`/`credential_access`/`sensitive_data_access`) are evidence-backed **descriptors** on graph nodes, kept separate from **risk modifiers** (`execution_locus`/transport/auth/mutability/operator). `capability_coverage` (unknown|partial|complete) makes *absence-is-not-falsehood* explicit; a capability is asserted only with citable evidence (declining beats guessing — the ADR-0039 lesson). `method` (declared|curated|inferred) is orthogonal to `source` (ADR-0035). A version-independent `capabilities/<identity>.yaml` corpus keyed by `openaca:identity` (ADR-0038) is distinct from advisory overlays. MCP tool-list enumeration is out (it requires running the server). **Amends ADR-0022**: capabilities emit in the BOM as component descriptors; exposure scores/cards stay out (BOM schema `0.2 → 0.3`).
- [ADR-0042 — Use `bom-ref` for occurrences and optional source-stable identity for cross-BOM joins](0042-source-stable-optional-component-identity.md): OpenACA has two component identifiers: `bom-ref` for exact within-BOM occurrences and optional, version-independent, role-qualified `openaca:identity` for cross-BOM joins. Local aliases are display-only; unknown-source components remain occurrence-local. Matching stays on typed source coordinates, and containment enters identity only when a plugin is the authoritative namespace for a private child. Agent BOM schema advances to 0.4.
- [ADR-0043 — Surface the agentic taxonomy by default; carry all list-valued families in machine formats](0043-default-taxonomy-surfacing.md): the default text card renders `owasp_agentic_top10` only (one `owasp-asi: <CODES>  [owasp-agentic-top-10-2026]` line per finding); JSON and SARIF carry the full `taxonomies` block under a `taxonomies` key distinct from posture's `standards`; absent families emit nothing. Extends ADR-0035's taxonomy-travel principle to vulnerability findings' JSON/SARIF output and **amends ADR-0016's** enumerated JSON envelope.
- [ADR-0044 — Make the agent the BOM root](0044-agent-bom-root.md): a BOM describes one **agent** (one runtime plus its composed context), not a place; a scan emits as many BOMs as agents found, each with the agent as `metadata.component`. Construction builds **one graph per agent**, each with the agent as its single target root, so attribution-by-containment (ADR-0037) is unchanged; a combined graph is not viable because `Graph.validate` rejects the two-parent node a shared file would create. Kind and composition source (`installed` | `declared`, both explicit) are independent axes — a kind is never qualified by where it runs, and where it runs is deliberately absent from the document because it changes nothing a BOM decides. More than one kind may read the same file with no ownership or precedence concept needed, since one BOM per agent removes the attribution question an ownership model would arbitrate. Rejects agent-as-a-tag (an agent with nothing configured would be invisible, and it revives the `attributed_to` encoding ADR-0037 retired), a four-valued placement property (only installed-versus-declared decides anything, and `production agent` mixes durability with role so a serverless managed agent cannot be expressed), and agent-as-a-component-row (unwieldy at 200 agents; needs a dishonest CycloneDX type). Discovery returning a **list** is the property that cannot be retrofitted. Two migration costs fall on the one implemented kind: kind-named node-key root labels rename **every** `bom-ref` once (diffs match on `bom-ref`, so the first post-upgrade scan reports total churn), and the hosted side records a single latest BOM per asset — so uploads keep today's one-BOM contract and resolving latest-per-kind **gates the second kind**, not this change. Design and the 18-situation evaluation: `docs/specs/multi-agent-support.md`.
- [ADR-0045 — Give an agent its own kind property; key it on asset, kind, and agent id](0045-agent-identity-keying.md): an agent carries its runtime in `openaca:agent_kind`, **not** in `openaca:identity` — identity means "a specific logical component" format-wide (ADR-0038/0042), and a runtime kind is a *category*, so two Cursor agents are two different agents sharing a type rather than two occurrences of one. Settled by ADR-0044's shape: the agent is `metadata.component`, never a `components[]` row, so it shares no table or group-by with component identities and reusing the field buys nothing. An agent's instance key spans two layers — the envelope's asset external id says *which* place, the document says *what sort of* agent — giving **(asset, kind, agent id)**. The composition source is descriptive and not part of the key, which is why it is safe to carry when place identity is not; the `openaca:agent_id` discriminator is required only for kinds with same-kind multiplicity — **cardinality itself is not BOM vocabulary**, only a scanner-internal declaration deciding whether a kind emits the field, which makes the present-iff rule a registry-dependent scanner self-check rather than anything the format expresses — and it is named for an **id** because it is part of the key drift pairs on — where a surface exposes both an immutable identifier and a renameable label (Bedrock's `agentId` beside `agentName`) the id is the only correct source, or a rename reads as a delete plus an add; the label belongs in the standard CycloneDX `metadata.component.name`; `bom-ref` stays the within-document key, prefixed `root/` — not `agent/`, which would share a namespace with the `agent` component type (a subagent, identity `agent/reviewer`), while a `startswith` test on that prefix decides whether a stored BOM is graph-backed. Two workstations with identical configuration are separate instances with observably identical compositions (machine-independent node keys), which is the definition-versus-place split. Also rejects an agent-qualified node-key prefix (`root/{kind}/<rel>`): the path label separates *roots within one scan*, not kinds, and each BOM is already single-kind — root labels are named for the kind that **owns the root**, which additionally fixes a pre-existing absolute-path fallback for files one runtime compat-reads from another's config root. Rejects kind-shaped identity, a name-suffixed kind (breaks the fleet-wide equality test), a place-qualified kind (makes `bom-ref`s machine-dependent, losing same-configuration recognition), a stored definition digest, and place *identity* in the document (the redaction contract keeps it in the upload envelope; only the categorical composition source is safe). Adds a BOM-pairing step to diffing, which today matches only within a single document pair.
- [ADR-0046 — Express agent scan completeness with the capability coverage vocabulary](0046-agent-coverage.md): an agent carries `openaca:composition_coverage`, reusing ADR-0041's `unknown | partial | complete` (no parallel taxonomy) — the name is qualified so it is not read as the per-component `openaca:capability_coverage`, which draws from the same levels at a different scope — resolved **per composition source**, not fixed per kind — and not per place, since the same runtime is blind to the same things in a sandbox as on a workstation. Coverage measures **discovery, not matchability** — a component with no advisory coordinate (a remote MCP server, ADR-0020) is fully discovered, and the implementation behind a declared tool is not composition, so a fourth "opaque backing resource" gap was withdrawn as mislabelling a managed agent partial. **The level only is emitted**: the three observability gaps behind a `partial` verdict (activation unobservable, registration unobservable, materialized at runtime) stay spec analysis, because they are derivable from (kind, composition source) which the BOM already carries, and because the vocabulary has a known hole — a surface a runtime declares but the scanner does not yet parse fits none of them. Adding a reasons property later is additive. `complete` requires every surface to be file- or API-declared. Rejects a bespoke verifiability vocabulary, a single boolean flag, per-kind coverage, and publishing the reasons now (premature, not wrong). Records the counterintuitive result that managed agents are *more* statically observable than framework agents: code defeats us, not remoteness.
- [ADR-0047 — One text card per agent, one machine document per scan](0047-per-agent-scan-output.md): text prints one card per agent while `--format json` stays a single document with a flat findings list plus an `agents[]` array (an exposure report carries it too), and `--format github` stays an annotation stream with per-agent attribution resolved against the finding's own agent graph; rejected NDJSON scan output (splits the flat findings list, orphans scan-wide totals, breaks `json.load`) and agent-on-findings-only (hides a zero-component agent).
- [ADR-0048 — Compile source-based policy restrictions](0048-source-based-restrictive-policy-compilation.md): policy names exact host-recognizable source/configuration values, not `bom-ref`, identity, digest, display names, or patterns; scan evidence evaluates policy but does not become policy syntax. Compilation only adds restrictions and reports a match as not enforceable when no exact host-native restriction exists.
- [ADR-0049 — Compile per endpoint and distinguish expected from observed enforcement](0049-endpoint-policy-compilation-and-observed-enforcement.md): compilation combines admission and risk gates into one endpoint-specific expected policy; host source selection and settings acceptance are separate observed facts, so a generated artifact is never reported as enforcement by itself.

- [ADR-0050 — Register one asset per machine and upload one BOM per agent](0050-collector-upload-cardinality.md): a sync registers **one asset — the machine, keyed on hostname — and sends one upload per discovered agent**, with the registration payload, its cached `asset_id`, and the upload envelope all unchanged: the hosted side resolves the agent from `metadata.component` in the document, so the wire needs no new field to say which agent an upload describes. An agent whose upload fails on the network goes to the pending cache and retries later while the others stand — retry becomes per-agent, which is correct only because the hosted side tracks each agent's state separately. Rejects **one asset per agent** (the asset carries owner, team, and remediation route, all properties of the *machine*; splitting doubles the asset count for one laptop, makes "how many machines are affected" unanswerable without a dedup rule, and breaks the single-`asset_id` registration cache — an agent is a child of an asset, not a replacement for one), **one request batching an array of BOMs** (churns a shipped request contract for a case that cannot occur while one kind ships, and converts a per-agent network failure into all-or-nothing), **a new envelope field naming the agent** (a second source of truth for a fact the document already carries, and the two can disagree — the in-BOM one is what the schema validates), and **refusing to upload when several agents resolve** pending a hosted capability advertisement (the hosted side gains per-agent awareness in parallel, so the guard would protect a window that never opens and then block correct uploads until someone deleted it). Cost: N requests per sync where there was one — one today, worth revisiting only for a kind with same-kind multiplicity. Design: `docs/specs/collector-agent-rooted-uploads.md`.
- [ADR-0051 — Extend the upload redaction contract to BOM metadata](0051-redaction-covers-bom-metadata.md): ADR-0003's redaction boundary is enforced by three layers — the collector's `_redact_payload_for_remote`, `enforce_remote_upload_contract`, and the hosted validator — and **all three walk `bom.components[*].properties` and stop**, so `bom.metadata` has never been scanned. The boundary is **every string in `bom.metadata` the collector synthesizes** — `metadata.properties`, `metadata.component.properties`, and `metadata.component.name` — *not* every `openaca:*` property: the prefix filter selects the property lists but does not define the scope, and the display label carries no prefix at all. Safe only by accident: the sole metadata value the collector writes is a literal it constructs itself. The agent-rooted migration ends that by putting the agent's own properties in `metadata.component.properties` — including `openaca:agent_id`, which `docs/specs/multi-agent-support.md` states the schema **does not constrain** — so the block stops being one the collector authors entirely. Still safe today only because the one shipped kind is a singleton (`agent_id` absent, label the literal `Claude Code`): the same accident, one layer over. The scope extension lands **before** anything writes there. An earlier version of this decision covered only the `openaca:*` property lists and missed `metadata.component.name`, which is emitted from unconstrained `AgentInstance.display_name` and is the literal `Claude Code` today only because the one shipped kind hardcodes it — the same "safe by accident" the ADR exists to end, and a contradiction with the spec's whole-metadata invariant that survived three review rounds. Redaction is precise enough not to mangle a legitimate label: `my-org/agent` is untouched because the embedded-path rule requires the `/` to follow a non-word character. Rejects **forbidding machine-derived metadata by convention** (enforces a data rule with a coding rule, holding only as long as every future author knows it, while the likeliest offender is a value the scan path already fills with an absolute path), **covering only `metadata.component.properties`** (fixes the instance, not the gap; `metadata.properties` is older and holds the riskier value), **relying on the hosted validator** (same blind spot, and a violation caught server-side has already crossed the network), and **scanning the whole document** (would reject legitimate pass-through CycloneDX content the collector never synthesized). Watch: a stale offline-cache payload is validated on replay by the new enforcer, so an upgrade can discard a cached payload a previous version would have sent.

- [ADR-0052 — Register Cursor as the second agent kind, presence-only for plugins](0052-cursor-agent-kind.md): Cursor registers as kind `cursor`, singleton, at **both** composition sources, covering MCP servers, skills, subagents, commands, plugins in **two** manifest formats, and plugin-bundled hooks; `permissions.json` ships as a **posture** surface rather than composition — it is not a separate component but the same MCP servers plus the question of which may auto-run, which Claude Code answers with a per-server `autoApprove` field and Cursor with a standalone file, so it needs a new collector but feeds the **same** rule (modeling it as composition would double-count every server). **The desktop app and the separately-distributed `cursor-agent` CLI are ONE kind** — shared config root, same MCP/skill/subagent roots, and Cursor's own docs call the CLI *"the same agent with a different interface"* — so the CLI's extra surfaces (`cli-config.json`, `<p>/.cursor/cli.json`, `CLAUDE.md`/`CLAUDE.local.md`) are additions to this kind's spec, not a second kind. Decided on an **implementation audit of both programs, not a documentation review**, and several documented facts did not survive: **neither program references `.codex/agents`** despite a documented six-root table (`.codex/skills` is real — the subagents table appears copy-pasted from it), the Claude/Codex compatibility reads sit behind an extensibility flag that **defaults to on** (stored in the editor state DB, so not file-readable), the plugin manifest resolves through an ordered candidate list **including `.claude-plugin/plugin.json`** with a manifest-less bundle loading via folder discovery, and **`CURSOR_CONFIG_DIR` relocates only `permissions.json` and the CLI config** — not `mcp.json`, skills, subagents, plugins, or hooks, which resolve from home directly. Plugins are **presence-only** — no `enabled`/`active` property at all, absent rather than `false` — because enable state is a **server call**, not a file we failed to parse; local state holds only enabled, numeric, nameless ids. Cursor's Claude-Code interop is **wider than either project documents** and includes Claude Code's **install lockfile** (entries carry arbitrary absolute install paths, so directory enumeration is insufficient) and its `settings.json` `enabledPlugins` — meaning the two kinds' plugin sets are **not independent**. Coverage is `partial` at both sources for **different** reasons, split three ways by closability: not-on-disk (server calls), on-disk-but-not-where-a-scan-looks (the flag; a remote window's other half), and deferred-by-choice (Rules/`AGENTS.md`/`CLAUDE.md`). Cross-reads are **composition, never evidence** (a `.claude`-only tree declares no Cursor agent; `.agents/skills/` is the lone exception while Cursor is its only registered reader). Rejects **`enabled: false` for cached-but-disabled plugins** (fabricates a verified negative), **inferring activation from cache presence** (disabling retains the cache), **building a `.codex/agents` surface** (reports components no agent has), **treating `.claude/*` as declared evidence** (a phantom near-empty Cursor BOM for every Claude-only repo), **`plugin/cursor/{name}` identity** (`canonical_component_identity` mints cross-BOM identity from any ≥2-slash string with no provenance check, so it would back real identity with a self-declared `name`), **excluding `mcp_auto_approve`** (true that `mcp.json` has no auto-approve field, but `permissions.json` is readable and its `mcpAllowlist`/`autoRun` are exactly that posture — reverses an earlier reading), **inventorying `skills-cursor/`** (vendor built-ins Cursor's own docs say to ignore; a sibling of the user root, not a variant spelling), **shipping Rules/`AGENTS.md`/`CLAUDE.md`** (not configuration — instructions given to a model, naming and versioning nothing, so no component to carry and no advisory to match; a prompt-injection question, not a composition one), and **treating the CLI as separate or deferring it** (double-counts one agent's config; a repo declaring `.cursor/` gives no signal which program reads it). Costs: plugin inventory is a systematic over-approximation, and two surfaces resolve conflicts in **opposite** directions (subagents first-wins/project-beats-user; commands last-wins/user-beats-project). Watch: the marketplace cache layout and `.cache-complete` sentinel are undocumented, so a layout change fails **silently** to zero plugins. Spec: `docs/specs/cursor-agent-kind.md`.

- [ADR-0053 — Parameterize repo-mode composition by surface descriptor; fork endpoint seeding per kind](0053-repo-surface-descriptor.md): repo mode and endpoint mode are Claude-specific in **different ways**, so they get **different treatments**. Repo mode (`descend`, `_find_plugin_roots`, `_add_project_skills`, `_add_repo_standalone_components`, …) is kind-specific only in its **string literals**, wrapped around ~600 lines of kind-neutral machinery encoding already-fixed bugs — two-root gitignore threading, the `exclude_under` single-parent discipline, symlink containment, ADR-0039 launch-dependency attachment, the normalizer/`occurrence_key` contract — so it is **parameterized** by a frozen `RepoSurface`/`PluginFormat`/`BundledLayout` descriptor in a neutral `tools/repo_surface.py`, defaulting to a verbatim `CLAUDE_CODE_SURFACE`. Endpoint mode (`_seed_endpoint`) is kind-specific in its **control flow** — settings-layer precedence, `claude_install`, `installed_plugins.json ∩ enabledPlugins`, tier-2 lockfile walking, none of which Cursor has an analogue for — so it is **forked** per kind. Shared helpers get **public aliases** rather than cross-module underscore imports. `graph_build` still never imports `agent_kinds`. The parameterization lands as its own change with **zero second-kind entries**, so the existing suite is an uncontaminated regression gate with a golden-graph assertion. Rejects **forking repo mode too** (duplicates 600 lines of hard-won correctness; lower risk for one release, higher risk thereafter), **parameterizing endpoint mode** (a descriptor expressive enough for both becomes ~10 optional callbacks — a fork wearing indirection, while risking shipped Claude behavior), **putting the descriptor in `graph_build` or under `agent_kinds/`** (invites the import cycle the one-way rule forbids), **importing helpers as privates** (an interface with no declaration), **landing both changes together** (the regression gate stops being a gate), and **extending `_registry_pattern_matches` by hand** (already four special-cased globs; `pathspec` is already a dependency, and compiled git-wildmatch is behavior-preserving once the two slash-anchored patterns regain their at-any-depth `**/` prefix). Watch: the descriptor crosses the placement/content boundary in exactly one place (`_parse_default_mcp`'s bundled MCP filename) and should stay the only one, and any `Callable`-typed field means it has drifted into the strategy object this rejected.

- [ADR-0054 — A config-root override is a per-kind capability; Cursor declares none](0054-per-kind-root-override.md): `--config-dir` is granted only to a kind for which **naming a root fully specifies the target** — no part of its composition derived from the home directory once a root is named. Claude Code qualifies (its home is consulted in exactly one place, the default-root function, and it reads no other runtime's directories); **Cursor does not**, because an installed Cursor is gathered from **three** places and a root override moves only one: Cursor's own root (moves), `permissions.json` (own axis — `CURSOR_CONFIG_DIR` then `XDG_CONFIG_HOME`, which the flag is deliberately not part of), and another runtime's skill roots `~/.claude/skills`/`~/.codex/skills`/`~/.agents/skills` (never under Cursor's root). **For Claude Code home is a default; for Cursor home is an ingredient.** So `--kind cursor --config-dir` is rejected and an installed Cursor scan always resolves `<home>/.cursor` plus the invoking user's home; `--kind` stays optional, mandatory only alongside `--config-dir`. No caller loses anything — tests needing a hermetic Cursor root already fake `Path.home` because the flag cannot isolate a Cursor scan. Rejects **keeping the flag with a documented warning** (the failure is silent — a mixed-home composition is indistinguishable in output from a correct one, so wrong inventory that does not say so is worse than a missing capability), **inferring the kind when only `--config-dir` is given** (correct exactly until a third relocatable kind registers, then the same command silently changes meaning), and **widening `--config-dir` to move all three groups** (breaks the relocation rule Cursor's runtime implements, and requires reconstructing home from a `.cursor` path's parent — the basename reconstruction the kind spec forbids). A **"treat this directory as home" override** is deferred, not rejected: it is the correct way to serve foreign-tree scanning and needs its own design, including whether it outranks `CURSOR_CONFIG_DIR` for `permissions.json`. Does **not** supersede ADR-0006, whose unconditional phrasing describes the only kind that then existed. Costs: scanning a copied config, mounted image, CI cache, or another account's tree as a Cursor endpoint is unsupported; the rule is easy to get wrong permissively — a kind reading *anything* home-derived after a root is named does not qualify. Watch: implementation follows this decision, so until it lands the CLI still accepts a flag this ADR forbids. Spec: `docs/specs/cursor-agent-kind.md` "CLI surface".

- [ADR-0055 — Register Codex as the third agent kind, with readable enable state](0055-codex-agent-kind.md): Codex registers as kind `codex`, singleton, at **both** composition sources. Decided on an **implementation audit of the shipped Rust binary** (`0.147.0-aarch64-apple-darwin`), and the headline finding is that **Codex is Claude Code-shaped, not Cursor-shaped**: plugin enable state is a **file** (`[plugins."<name>@<marketplace>"] enabled` in `config.toml`, keyed byte-identically to Claude Code's `enabledPlugins`), the cache layout is Claude Code's (`plugins/cache/<mkt>/<name>/<ver>/` plus a `[marketplaces.*]` registry carrying `source_type`/`source`/`last_revision`), hook events are **PascalCase sharing Claude Code's names** (plus a Codex-only `PermissionRequest`), and `$CODEX_HOME` relocates the whole root. Conversely Codex is **not a cross-reader**: `.claude/skills`, `.claude/agents`, `.agents/skills`, and `installed_plugins.json` each have **zero** references — its only cross-runtime read is the `.claude-plugin/plugin.json` manifest **format**, as the second candidate after `.codex-plugin/plugin.json` (4 cached bundles carry only Claude's and all are `enabled = true`, which is what proves the fallback live). In scope: MCP (`[mcp_servers.*]` inline in TOML, carrying `enabled`, `url`, `bearer_token`, `http_headers`), skills, **subagents as user-scope TOML** (`~/.codex/agents/*.toml` — `.codex/agents` has zero refs, so a project cannot declare one), plugins in both formats, plugin-bundled hooks, and project `.codex/hooks.json`; `rules/*.rules` (a `prefix_rule(...)` **DSL**, not JSON) and `[projects.*] trust_level` ship as **posture**. **Plugins and MCP servers carry real `enabled` state** — this differs visibly from ADR-0052 and is the *same* principle on different evidence: that ADR withheld the property because Cursor's state is a server call so the value would be **fabricated**, whereas Codex writes it to a file we parse, and withholding a readable fact is the mirror error. Everything installed is inventoried regardless, since a disabled plugin is still installed and one edit from active. **There is no commands surface** — both other kinds have one, Codex does not. `AGENTS.md` is **out on Claude Code's rule** (55 refs, more than any in-scope surface, and still not configuration: it names nothing, versions nothing, resolves to no artifact; no registry pattern or parser touches an instruction file for **any** kind, and Claude Code ignores its own `CLAUDE.md`) — so **no taxonomy ADR is required**, and every surface maps into the ADR-0019/0031 closed sets. `skills/.system/` is excluded **structurally** by its `.codex-system-skills.marker` rather than by a name list — notably those are exactly the six names Cursor hardcodes and its own spec flags as drift-prone. **ADR-0052's revisit trigger does not fire**: it made `.agents/skills/` Cursor evidence while Cursor was its only reader and flagged it for a Codex kind, but Codex does not read it, so the Cursor claim survives unchanged. Rejects **modeling Codex on Cursor** (the evidence shows the opposite; would fork what should be parameterized and make plugins presence-only for no reason), **presence-only for consistency** (cosmetic consistency applying ADR-0052's conclusion where its premise is false), **inventorying only enabled plugins** (hides installed-but-off artifacts, precisely the population a supply-chain tool should surface), **shipping `AGENTS.md`** (contradicts ADR-0052 without superseding it; leaves Claude Code ignoring `CLAUDE.md` while Codex reports `AGENTS.md`), and **building a `.codex/agents` surface** (no code path reads it; the docs error is upstream of both Cursor and Codex). Coverage **splits by source** — `complete` at `declared` (all four surfaces a Codex repo declares parse in full; Cursor is `partial` there only for its non-file-readable extensibility flag, which Codex has no equivalent of) and `partial` at `installed` for five gaps, two of which (`managed_config.toml`, profile layering) close by parsing, unlike Cursor's dominant gap. The split is the discipline stated: a baseline is argued from a named gap at THAT source, never inherited from the other and never set conservatively because a kind is new. Costs: a new TOML config parser and a new TOML subagent parser, and `mcp_auto_approve` must be generalized (it hardcodes `active_in=["cursor"]`), which touches a shipped Cursor path. Watch: the cache layout is undocumented, so a change fails **silently** to zero plugins; and a local marketplace whose `source` points into `~/.claude/plugins/local/` means Codex and Claude Code realize the **same bundle** — the corpus's first genuine same-artifact-two-kinds case, deliberately left unsettled here. Spec: `docs/specs/codex-agent-kind.md`.

- [ADR-0056 — Codex honors `$CODEX_HOME` and accepts `--config-dir`](0056-codex-root-override.md): the counterpart to ADR-0054, and the case showing its refusal was **Cursor-specific rather than the general rule**. ADR-0054 grants the flag only to a kind for which naming a root fully specifies the target; Codex qualifies because `$CODEX_HOME` (60 refs) relocates the **whole** root and every in-scope surface — `config.toml`, `skills/`, `agents/`, `plugins/`, `rules/` — lives beneath it, while Codex reads **no** other runtime's tree (`.claude/skills`, `.claude/agents`, `installed_plugins.json` all zero refs). The multi-home condition ADR-0054 refused on is simply absent, so a scan rooted at an overridden directory is complete rather than stitched; `root_override_refusal` is `None`. `--config-dir` still requires `--kind` once multiple kinds are registered — that guard is about ambiguity **between** kinds, unrelated to whether any kind can honor the flag. **Does not supersede ADR-0054**, whose decision for Cursor stands: this exercises that ADR's per-kind mechanism rather than overturning it, and recording the *positive* answer makes the mechanism's two-sidedness visible so the next kind reasons from its own shape instead of copying whichever precedent it read first. Rejects **refusing for symmetry with Cursor** (symmetry between kinds is not a value the mechanism holds; each kind declaring its own truth is), **honoring the env var but refusing the flag** (incoherent — if the root relocates and an env var may relocate it, there is no principled reason to reject the explicit form, and it would leave endpoint tests unable to root a fixture without mutating the environment), and **amending ADR-0054 in place** (accepted ADRs are immutable). Enables Codex endpoint tests to root a fixture directly, without the `Path.home` monkeypatching every Cursor endpoint test needs. Watch: `managed_config.toml`'s distribution path is **unaudited**, and an admin layer outside the root would reintroduce exactly the split-home problem ADR-0054 refused on.

- [ADR-0057 — Endpoint seeding becomes descriptor-driven; replaces the endpoint half of ADR-0053](0057-parameterize-endpoint-seeding.md): fires ADR-0053's **own stated revisit trigger** — *"if a third kind's endpoint seeding turns out to share structure with an existing one … the endpoint half of this decision should be reopened rather than worked around."* That ADR forked endpoint mode because Cursor had **no analogue** for settings layers, an install lockfile, or readable enable state; Codex has an analogue for **each** (`managed_config.toml` → `config.toml` → profile → project; `plugins/cache/*` plus `[marketplaces.*]`; `[plugins."x@y"] enabled`; `last_revision` for `gitCommitSha`), with enable-map keys byte-identical in format. So Codex drives Claude Code's `_seed_endpoint` through a descriptor instead of bringing a third fork. **Replaces only the endpoint half**: ADR-0053's repo-mode half (`RepoSurface`/`PluginFormat`/`BundledLayout`, the one-way `agent_kinds → graph_build` dependency, the public-alias rule, the uncontaminated regression gate) remains in force for all three kinds — so frontmatter carries `supersedes: null` and **ADR-0053 is not marked superseded**, because the repository's supersession discipline assumes whole replacement and retiring a live repo-mode decision three kinds depend on would be the worse misstatement. **Scope of the evidence is stated explicitly**: the audit establishes the endpoint *data model* matches, **not** that every `_seed_endpoint` branch has a Codex counterpart (the tier-2 lockfile dependency walk has no audited analogue), so implementation must confirm branch-by-branch, and where a branch has no counterpart the descriptor carries an **absence** — an empty tuple or `None`, never a callback. Claude Code's shipped behavior must not change: values transcribed verbatim, with the same byte-identical golden-graph gate ADR-0053 required, zero Codex entries in that diff. Rejects **a third fork** (lower risk for one release, higher thereafter — every endpoint fix lands three times and the two kinds sharing a model drift apart), **importing Claude Code's seed privately** (an interface with no declaration), **marking ADR-0053 fully superseded** (retires a live decision), **deferring to implementation** (the fork/parameterize choice determines the composer's shape, so deferring means writing it twice or forking by default), and **generalizing eagerly for a hypothetical fourth kind**. Watch: repo and endpoint modes are now both parameterized but by **different** descriptors answering different questions (paths in a tree vs install-state locations) and should not be unified merely because both are descriptors; and any `Callable`-typed field means this has drifted back into the strategy object ADR-0053 rejected.
