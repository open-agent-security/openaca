# 0.7.0 — a credential in an MCP header is posture, not a secret scan

A remote MCP server's configuration can carry its own credential:
`"headers": {"Authorization": "Bearer …"}` in an `mcp.json`, a
`.claude/settings.json`, or a Codex `http_headers` table. Those files get
committed, copied and shared, and the credential travels with them whether or
not the connection itself is over HTTPS. Until now OpenACA said nothing about
it, because it had no rule whose claim was *inline credential storage* rather
than *this token is real*.

This release adds that rule, and spends most of its commits on getting the
attribution right: when several settings scopes contribute to one server, the
finding names the scope that actually owns the header.

Design: ADR-0065 (what is reported and what is not), ADR-0066 (the attribution
bar), `docs/posture/openaca-posture-mcp-header-credential.md`.

## Highlights

- **`openaca-posture-mcp-header-credential`** — medium severity, high
  confidence, CWE-798. Fires once per enabled remote server with a nonempty
  literal value in `Authorization`, `Proxy-Authorization`, `Authz`,
  `X-Api-Key`, `Api-Key` or `X-Auth-Token` (case-insensitive), across JSON
  `headers` and Codex TOML `http_headers`, in both `scan repo` and
  `scan endpoint` with `--include-posture`. Indirect references such as
  `${env:TOKEN}` or `${input:token}` do not fire; a literal fallback does.
  Dummy tokens fire deliberately: the finding is about where the credential
  lives, and it never establishes validity or exposure.

- **The finding names fields, never values.** Header values stay inside the
  transient posture pass. They are not copied into component refs, graph
  properties, BOM exports or the finding itself, so a scan of a manifest holding
  a live token does not become a second place that token is written down.

- **Provenance is resolved per header key within a scope.** Claude Code merges
  user, project, local and managed settings; a higher-precedence scope can own
  the `headers` block while another owns the `url`. The finding's `declared_by`
  is the scope that declares the credential-bearing header, keyed by exact
  header casing, and a scope that owns only a risk-relevant field still attaches
  to the right component through the new `component_source`. ADR-0066 states
  the bar: a missed credential is a defect, a neighbouring-scope attribution
  under a still-finer split is deferred.

- **Forged provenance is ignored.** The collector's provenance sidecars are
  trusted only as the `Path` objects the collector itself produces. A raw
  manifest cannot smuggle a same-named string key to redirect `declared_by` or
  the BOM attachment, for this rule or for `mcp-auto-approve`, which now uses
  the same owner resolution.

- **Codex and Cursor endpoint scans run the rule too**, with their own config
  and project roots, and MCP authentication sources are read by content before
  falling back to file suffix, so a JSON body under an unexpected name is still
  read as JSON.

- **Bug fixes.** `.gitignore` handling prunes ignored directory trees again
  when a negation pattern demonstrably cannot reach them, instead of walking the
  whole tree the moment any `!` rule exists; endpoint plugin walks stay limited
  to composed MCP sources.

## Install

`uv tool install openaca==0.7.0` or `pip install openaca==0.7.0`.

## Compatibility

Pre-V0 — no back-compat hedging.

- **`PostureFinding` gains `component_source: str | None = None`.** Optional
  and defaulted, so existing consumers of the published type keep working;
  `None` means "match on `declared_by.path`", the previous behaviour.

- **One new rule id** in posture output and in the Codex and Cursor agent
  kinds' rule lists. Like every posture finding it does not affect `--fail-on`
  exit codes.

- **BOM schema version stays `0.5`.** `tools/bom.py`, `tools/graph_build.py`
  and `schema/openaca-bom.schema.json` are untouched in this release. Recorded
  so the next release knows the check ran.

- **The overlay record schema is unchanged.**
