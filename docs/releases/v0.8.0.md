# 0.8.0 — vulnerability gates compile on real endpoints

A policy with a vulnerability gate used to refuse to compile if any component
on the endpoint lacked a supported advisory lookup coordinate. Ordinary plugin
containers, hooks and standalone skills have no such coordinate, so on most real
endpoints a policy asking only to block High or Critical vulnerabilities in MCP
servers could not be compiled at all.

This release keeps the gate and drops the all-or-nothing precondition.

Design: ADR-0064, `docs/specs/policy-compiler.md`.

## Highlights

- **Unqueryable components no longer abort compilation.** With
  `risk_gates.vulnerabilities` configured, every component that can be looked
  up is checked against fresh advisory data and blocked on a match. A component
  without a supported lookup coordinate is not blocked for being unqueryable,
  and still receives admission and posture evaluation. A finding on bundled
  content still blocks its owning plugin.

- **Coverage is reported, not implied.** The compile report gains
  `vulnerability_coverage` whenever a vulnerability gate is configured:
  `total_components`, `queryable_components`, and an `unavailable` entry per gap
  with the component label, source manifest, source locator and reason. Text
  output prints the counts and every gap, including the source location, so a
  dependency repeated across plugin manifests is distinguishable. An `allowed`
  decision is not a clean bill of health, and the report says what was not
  checked.

- **Real failures still fail closed.** A supported lookup that fails, or a
  matched advisory whose severity cannot be evaluated against
  `severity_at_least`, still fails compilation without replacing the previous
  artifact.

## Install

`uv tool install openaca==0.8.0` or `pip install openaca==0.8.0`.

## Compatibility

Pre-V0 — no back-compat hedging.

- **`compile_endpoint_policy` succeeds where it used to raise.** An endpoint
  with non-queryable components and a vulnerability gate previously raised
  `PolicyEvaluationError("vulnerability gates cannot evaluate non-queryable
  component(s): …")`; it now compiles and reports the gaps. Callers that relied
  on that error to detect partial coverage should read
  `report["vulnerability_coverage"]["unavailable"]` instead.

- **New report field.** `vulnerability_coverage` is present only when a
  vulnerability gate is configured; no field is emitted otherwise.

- **BOM schema version stays `0.5`.** `tools/bom.py`, `tools/graph_build.py`
  and `schema/openaca-bom.schema.json` are untouched in this release. Recorded
  so the next release knows the check ran.

- **The overlay record schema is unchanged.**
