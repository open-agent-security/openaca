# ADR Index

Architecture Decision Records for OpenACA. The index is loaded into every
session by a hook; full ADRs are read on-demand when an entry looks
related to the work at hand.

**When to read full ADRs:** before changing logic in the area an ADR
covers. Each entry's one-liner is a hook — if it sounds at all
adjacent to your task, click through.

**When to write a new ADR:** when you make a decision where the
rejected alternative is *plausible* and *likely to be re-suggested*,
and the reason isn't obvious from the code. See `TEMPLATE.md`.

**Supersession discipline:** ADRs are immutable once accepted. If a
later decision contradicts an existing ADR, write a NEW ADR with
`supersedes: NNNN` in its frontmatter, and update the old ADR's
frontmatter to `status: superseded` + `superseded-by: NNNN`. Never
edit an accepted ADR's body in place — old PRs need to be readable
against the rules in effect at the time.

## Active

- [ADR-0005 — V0 manifest parsers are POSIX-only](0005-manifest-parsers-posix-only.md): `_classify_command` is `Path(command).stem` (case-sensitive, no backslash/PATHEXT handling); rejected always-lowercase, Windows-shape heuristic, and known-launcher allow-list because each either introduces POSIX false positives or ships V0-out-of-scope Windows support.
- [ADR-0006 — openaca scan subcommands, claude-plugin ecosystem, attribution](0006-openaca-scan-subcommands-and-attribution.md): Explicit `repo`/`endpoint` subcommand split (subcommand is **required**; no no-subcommand fallback — the back-compat shim was removed pre-launch); `endpoint` defaults to `$CLAUDE_CONFIG_DIR` else `~/.claude` and accepts optional `--project`; `claude-plugin` as a recognized `affected[*].package.ecosystem` so plugin advisories match via `_match_versioned`; `attributed_to` mirrored on ComponentRef and Finding so plans 008 and 009 can tag "via plugin X" findings. **The `attributed_to` fields provision is amended by ADR-0037** — attribution is now derived from the composition graph (CycloneDX `dependencies[]` edges + nearest-plugin-ancestor), not stored on `ComponentRef`/`Finding` or emitted as the `openaca:attributed_to` BOM property; the SARIF/JSON `attributed_to` output field is retained but graph-derived. The subcommand split and `claude-plugin` ecosystem decisions stand.
- [ADR-0009 — V0 ships OpenACA overlays, not OpenACA advisory IDs](0009-overlay-only-v0.md): V0 overlays use upstream IDs (`GHSA-*`, `CVE-*`) and carry only `database_specific.openaca`; scanner queries OSV.dev, dedupes by alias graph, then applies bundled overlays; no `--db` or `--overlays` CLI flag in V0. Query-shape details are amended by ADR-0027.
- [ADR-0011 — Add opt-in LLM seed annotation with framework context](0011-llm-assisted-seed-annotation.md): seeders keep deterministic discovery and alias deduplication, but `openaca seed --llm-provider <openai|anthropic> --llm-model <name>` can draft OpenACA annotations from OSV records plus `docs/frameworks/*.md`; LLM output writes candidates only, never canonical overlays.

- [ADR-0016 — Separate agent component source identity from scan context in output](0016-agent-component-identity-and-scan-output.md): scan output separates component identity, source information, and scan context; `declared_by`, `component_path`, and `active_in` explain direct vs plugin-bundled installation. Matching-coordinate details are superseded by ADR-0031. **Amended by ADR-0043**: the vulnerability envelope gains a top-level `taxonomies` key; the three-identity-layer separation stands.
- [ADR-0017 — Endpoint scan keeps project context opt-in, with an unconditional reminder note](0017-endpoint-scan-cwd-project-default.md): amends ADR-0006 by adding an always-shown note when `--project` is omitted from endpoint scans (educational mechanism to help testers discover the flag without surprise). Rejects cwd-as-default (recursive home-tree walk + double-counting), overlap-guard heuristics, and cwd-marker hint detection in favor of a single uniform rule: opt-in via `--project`, note when omitted. The `detected config_dir=..., project=...` line is also now emitted unconditionally for scan-scope transparency.
- [ADR-0020 — Remote MCP server inventory via `mcp-remote` identity namespace](0020-remote-mcp-server-inventory.md): extends the MCP parser to emit refs for URL-bearing entries (HTTP/SSE/streamableHttp) under `mcp-remote/<normalized-host-path>` identity, source-less per ADR-0019; closes the round-1 "0 MCP servers" interpretability gap, parallels the existing `mcp-stdio/` namespace, records transport in `extra.transport` and original URL in `extra.url`. No OSV federation for remote MCPs.
- [ADR-0021 — Use skills CLI lockfiles as source provenance for direct skills](0021-skills-lock-source-provenance.md): endpoint scans keep direct skills direct, preserve activation paths, and use global `.skill-lock.json` / project `skills-lock.json` only as scanner-observed source provenance under `extra.source_provenance`; `attributed_to` remains plugin-only and recovered skill source does not affect advisory matching in V0.
- [ADR-0022 — Agent BOM is open, CycloneDX-compatible, and the scanner's composition IR](0022-agent-bom-open-cyclonedx.md): Agent BOM schema and single-target generation are open; CycloneDX JSON is the interchange format with `openaca:*` properties; regular scans build an internal Agent BOM before matching; findings stay separate and reference BOM component IDs. **Amended by ADR-0041**: capability facts are component descriptors emitted in the BOM (`openaca:capabilities` / `openaca:capability_coverage`); exposure scores/cards stay out. The composition-only principle stands.
- [ADR-0023 — Ship Claude Code integration as a thin plugin wrapper](0023-claude-code-plugin-distribution.md): Claude Code integration lives in a separate plugin repo that invokes the published `openaca` CLI; scanner logic, matching, BOM schema, posture rules, and parsers stay in core; initial plugin is explicit-invocation only, with no hooks, monitors, MCP server, or automatic blocking.
- [ADR-0026 — Keep only persistent install script](0026-direct-uvx-for-one-shot-scans.md): supersedes ADR-0025; keep `scripts/install.sh` as the only maintained shell installer, remove `scripts/scan.sh`, and lead README quickstart with install-then-run rather than a no-persistent-install path.
- [ADR-0027 — Match OSV.dev using ecosystem-specific query shapes](0027-osv-query-semantics.md): OSV federation no longer assumes every internal PURL is an OSV query key; npm/PyPI use package PURLs, GitHub commits use OSV commit queries, Git refs use OSV `GIT` package/version queries, and generic Docker image refs stay inventory-only until a supported advisory source exists.
- [ADR-0028 — Expose domain logic via a curated `openaca.core` consumption facade](0028-openaca-core-consumption-facade.md): downstream consumers depend on a pinned, curated `openaca.core` facade (`ComponentRef`, BOM parse/build, `collect_osv_queries`/`OsvQuery` + provenance stamping, `match`, severity normalization, attribution) instead of importing `tools.*` internals or reimplementing domain semantics; the facade is the supported consumption seam but **not** a stable public API pre-V0 (consumers pin a version/SHA + contract test); the full `tools/`→`openaca/*` migration is deferred and absorbed behind the facade.
- [ADR-0031 — Separate graph identity from match coordinates](0031-match-coordinates.md): vulnerability matching uses derived match coordinates from PURL, Git metadata, unpinned package launches, or `openaca:match_coordinate`; matching never falls back to graph identity. Clarified by ADR-0038 and amended by ADR-0042: `bom-ref` is the occurrence key and optional `openaca:identity` is the source-stable cross-BOM join key.
- [ADR-0032 — Use remote as the public upload CLI namespace](0032-remote-cli-namespace.md): supersedes ADR-0024's public `openaca fleet ...` command group; networked backend operations now live under product-neutral `openaca remote ...`, with endpoint collection exposed as `openaca remote sync endpoint`.
- [ADR-0035 — Classify findings by claim type; keep source attribution orthogonal](0035-source-orthogonal-finding-types.md): `finding_type` describes the claim (`vulnerability`, `posture`, `observation`), while `source` describes who made it; external scanner output is classified per rule, not forced into observations.
- [ADR-0036 — Defer skill-bundled dependency vulnerability coverage](0036-defer-skill-dep-vuln-coverage.md): V0 keeps the narrow `.claude-plugin/plugin.json`-only dep classification; skill-adjacent deps stay `software-dependency`, native OSV federation is the sole vuln source, and the SkillSpector adapter skips SC4. The composition graph derives skill-dep scope from lineage and lands this coverage properly afterward.
- [ADR-0037 — Composition graph as the scanner's first-class IR, encoded in the Agent BOM](0037-composition-graph-ir.md): model composition as a nodes+edges graph built by recursive descent (parent-by-construction), keyed by occurrence identity (ADR-0031), encoded via CycloneDX `dependencies[]` (no `openaca:parent`); scope derives from lineage (replaces `_classify_dep_manifest`) and `attributed_to` is removed (derived from edges, in scanner + Fleet). Transitive package deps and typed edges deferred. Full design in `docs/specs/composition-graph.md`. Clarified by ADR-0038: `bom-ref` (= node.key) is the per-occurrence key; `openaca:identity` is the canonical join key.
- [ADR-0038 — `openaca:identity` is the canonical join key; `bom-ref` is the per-occurrence node key](0038-identity-join-key-vs-bom-ref-occurrence-key.md): establishes the two-key split: `bom-ref` (= graph `node.key`) wires exact occurrences and `openaca:identity` groups the same logical component. Amended by ADR-0042: identity is optional, source-stable, role-qualified, and version-independent; unidentified occurrences never cross-BOM join.
- [ADR-0039 — Resolve MCP-server launch targets to their dependency manifests](0039-mcp-launch-dependency-resolution.md): un-defers a scoped slice of ADR-0037's declaration-based attribution — `mcp_server` is no longer a leaf. A post-descent pass resolves each MCP node's launch target — an `npx`/`uvx`/`bunx <pkg>` whose name matches a local manifest — to that dependency directory and attaches its deps as `package` children, re-parenting root deps already under `target` (MCP wins) to preserve the single-parent invariant. Resolved deps are `agent-dependency` via the existing `scope_of` — **no scope-rule change** (ADR-0037 #7 stands). Everything else attaches nothing in Phase 1 — remote/external launches **and** local-path commands (`node ./x.js`, `python -m`), env-wrapped, or exotic launchers; on-disk package-manager **cache resolution** (external-`npx` transitive closures, local-path deps, concrete-version OSV match) is **Phase 2 (separate ADR)**.
- [ADR-0040 — Separate scan evidence from triage decisions](0040-scan-triage-command-boundary.md): `openaca scan` remains the evidence-collection layer, while `openaca triage` consumes scan artifacts to rank, explain, and recommend actions for component-centric exposure reports. `scan --report exposure` is allowed as the one-command shortcut, but both paths must share the same triage engine; reports stay outside the Agent BOM.
- [ADR-0041 — Model agent-component capabilities as first-class descriptors, extracted defensibly](0041-agent-component-capabilities.md): capabilities (`file_read`/`file_write`/`shell_exec`/`network_egress`/`credential_access`/`sensitive_data_access`) are evidence-backed **descriptors** on graph nodes, kept separate from **risk modifiers** (`execution_locus`/transport/auth/mutability/operator). `capability_coverage` (unknown|partial|complete) makes *absence-is-not-falsehood* explicit; a capability is asserted only with citable evidence (declining beats guessing — the ADR-0039 lesson). `method` (declared|curated|inferred) is orthogonal to `source` (ADR-0035). A version-independent `capabilities/<identity>.yaml` corpus keyed by `openaca:identity` (ADR-0038) is distinct from advisory overlays. MCP tool-list enumeration is out (it requires running the server). **Amends ADR-0022**: capabilities emit in the BOM as component descriptors; exposure scores/cards stay out (BOM schema `0.2 → 0.3`).
- [ADR-0042 — Use `bom-ref` for occurrences and optional source-stable identity for cross-BOM joins](0042-source-stable-optional-component-identity.md): OpenACA has two component identifiers: `bom-ref` for exact within-BOM occurrences and optional, version-independent, role-qualified `openaca:identity` for cross-BOM joins. Local aliases are display-only; unknown-source components remain occurrence-local. Matching stays on typed source coordinates, and containment enters identity only when a plugin is the authoritative namespace for a private child. Agent BOM schema advances to 0.4.
- [ADR-0043 — Surface the agentic taxonomy by default; carry all list-valued families in machine formats](0043-default-taxonomy-surfacing.md): the default text card renders `owasp_agentic_top10` only (one `owasp-asi: <CODES>  [owasp-agentic-top-10-2026]` line per finding); JSON and SARIF carry the full `taxonomies` block under a `taxonomies` key distinct from posture's `standards`; absent families emit nothing. Extends ADR-0035's taxonomy-travel principle to vulnerability findings' JSON/SARIF output and **amends ADR-0016's** enumerated JSON envelope.
- [ADR-0044 — Make the agent the BOM root](0044-agent-bom-root.md): a BOM describes one **agent** (one runtime plus its composed context), not a place; a scan emits as many BOMs as agents found, each with the agent as `metadata.component`. Construction builds **one graph per agent**, each with the agent as its single target root, so attribution-by-containment (ADR-0037) is unchanged; a combined graph is not viable because `Graph.validate` rejects the two-parent node a shared file would create. Kind and composition source (`installed` | `declared`, both explicit) are independent axes — a kind is never qualified by where it runs, and where it runs is deliberately absent from the document because it changes nothing a BOM decides. More than one kind may read the same file with no ownership or precedence concept needed, since one BOM per agent removes the attribution question an ownership model would arbitrate. Rejects agent-as-a-tag (an agent with nothing configured would be invisible, and it revives the `attributed_to` encoding ADR-0037 retired), a four-valued placement property (only installed-versus-declared decides anything, and `production agent` mixes durability with role so a serverless managed agent cannot be expressed), and agent-as-a-component-row (unwieldy at 200 agents; needs a dishonest CycloneDX type). Discovery returning a **list** is the property that cannot be retrofitted. Two migration costs fall on the one implemented kind: kind-named node-key root labels rename **every** `bom-ref` once (diffs match on `bom-ref`, so the first post-upgrade scan reports total churn), and the hosted side records a single latest BOM per asset — so uploads keep today's one-BOM contract and resolving latest-per-kind **gates the second kind**, not this change. Design and the 18-situation evaluation: `docs/specs/multi-agent-support.md`.
- [ADR-0045 — Give an agent its own kind property; key it on asset, kind, and agent id](0045-agent-identity-keying.md): an agent carries its runtime in `openaca:agent_kind`, **not** in `openaca:identity` — identity means "a specific logical component" format-wide (ADR-0038/0042), and a runtime kind is a *category*, so two Cursor agents are two different agents sharing a type rather than two occurrences of one. Settled by ADR-0044's shape: the agent is `metadata.component`, never a `components[]` row, so it shares no table or group-by with component identities and reusing the field buys nothing. An agent's instance key spans two layers — the envelope's asset external id says *which* place, the document says *what sort of* agent — giving **(asset, kind, agent id)**. The composition source is descriptive and not part of the key, which is why it is safe to carry when place identity is not; the `openaca:agent_id` discriminator is required only for kinds with same-kind multiplicity — **cardinality itself is not BOM vocabulary**, only a scanner-internal declaration deciding whether a kind emits the field, which makes the present-iff rule a registry-dependent scanner self-check rather than anything the format expresses — and it is named for an **id** because it is part of the key drift pairs on — where a surface exposes both an immutable identifier and a renameable label (Bedrock's `agentId` beside `agentName`) the id is the only correct source, or a rename reads as a delete plus an add; the label belongs in the standard CycloneDX `metadata.component.name`; `bom-ref` stays the within-document key, prefixed `root/` — not `agent/`, which would share a namespace with the `agent` component type (a subagent, identity `agent/reviewer`), while a `startswith` test on that prefix decides whether a stored BOM is graph-backed. Two workstations with identical configuration are separate instances with observably identical compositions (machine-independent node keys), which is the definition-versus-place split. Also rejects an agent-qualified node-key prefix (`root/{kind}/<rel>`): the path label separates *roots within one scan*, not kinds, and each BOM is already single-kind — root labels are named for the kind that **owns the root**, which additionally fixes a pre-existing absolute-path fallback for files one runtime compat-reads from another's config root. Rejects kind-shaped identity, a name-suffixed kind (breaks the fleet-wide equality test), a place-qualified kind (makes `bom-ref`s machine-dependent, losing same-configuration recognition), a stored definition digest, and place *identity* in the document (the redaction contract keeps it in the upload envelope; only the categorical composition source is safe). Adds a BOM-pairing step to diffing, which today matches only within a single document pair.
- [ADR-0046 — Express agent scan completeness with the capability coverage vocabulary](0046-agent-coverage.md): an agent carries `openaca:composition_coverage`, reusing ADR-0041's `unknown | partial | complete` (no parallel taxonomy) — the name is qualified so it is not read as the per-component `openaca:capability_coverage`, which draws from the same levels at a different scope — resolved **per composition source**, not fixed per kind — and not per place, since the same runtime is blind to the same things in a sandbox as on a workstation. Coverage measures **discovery, not matchability** — a component with no advisory coordinate (a remote MCP server, ADR-0020) is fully discovered, and the implementation behind a declared tool is not composition, so a fourth "opaque backing resource" gap was withdrawn as mislabelling a managed agent partial. **The level only is emitted**: the three observability gaps behind a `partial` verdict (activation unobservable, registration unobservable, materialized at runtime) stay spec analysis, because they are derivable from (kind, composition source) which the BOM already carries, and because the vocabulary has a known hole — a surface a runtime declares but the scanner does not yet parse fits none of them. Adding a reasons property later is additive. `complete` requires every surface to be file- or API-declared. Rejects a bespoke verifiability vocabulary, a single boolean flag, per-kind coverage, and publishing the reasons now (premature, not wrong). Records the counterintuitive result that managed agents are *more* statically observable than framework agents: code defeats us, not remoteness.
- [ADR-0047 — One text card per agent, one machine document per scan](0047-per-agent-scan-output.md): text prints one card per agent while `--format json` stays a single document with a flat findings list plus an `agents[]` array (an exposure report carries it too), and `--format github` stays an annotation stream with per-agent attribution resolved against the finding's own agent graph; rejected NDJSON scan output (splits the flat findings list, orphans scan-wide totals, breaks `json.load`) and agent-on-findings-only (hides a zero-component agent).

## Superseded

- [ADR-0033 — Separate scanner observations from advisories and posture](0033-observation-findings.md): superseded by ADR-0034. The separation of observations from advisories and posture (the three-family model) remains in force; the canonical skill coordinate kind is renamed from `skill-tree-hash` to `skill-content-hash`.

- [ADR-0034 — Use external scanners as observation sources](0034-external-observation-sources.md): superseded by ADR-0035. - [ADR-0024 — Keep Fleet collection opt-in with an endpoint inventory upload contract](0024-opt-in-fleet-cli.md): superseded by ADR-0032. The opt-in upload boundary and endpoint inventory contract remain, but the public CLI namespace moves from product-specific `fleet` to product-neutral `remote`.
- [ADR-0019 — Separate source ecosystems from agent component types](0019-source-ecosystems-and-agent-component-types.md): superseded by ADR-0031. The source-ecosystem/component-type separation remains, but source-less graph identities no longer match vulnerability advisories by `database_specific.openaca.component_identity`.
- [ADR-0029 — Make `openaca:identity` the agent graph occurrence key](0029-agent-graph-occurrence-identity.md): superseded by ADR-0042. Exact occurrences now use `bom-ref`; optional `openaca:identity` is source-stable and cross-BOM rather than alias-shaped.
