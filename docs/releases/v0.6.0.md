# 0.6.0 — OpenACA is local; a consumer gets a library

OpenACA could upload what it found to a hosted service. `openaca remote` stored
an API token, uploaded an endpoint's Agent BOMs, and fetched an organisation
policy from a server — and `tools/remote/config.py` defaulted its upload target
to one company's hostname. **All of it is gone in this release.**

The reason is scope. Examining one machine — which agents are installed, what
they are composed of, what is wrong with their configuration — is what OpenACA
is for, and belongs in the open. Being a client for one company's service, with
an account, a credential and that service's payload schema, is not; shipping it
here implied the project had a hosted half.

Removing a capability is only defensible if it becomes reachable somewhere
better, so this release also **publishes the surfaces the client used
privately**. Anything that wants to collect a machine's inventory, compile a
policy, or offer OpenACA's commands under its own name now does so through a
supported API rather than by reimplementing it or reaching into `tools.*`.

Design: `docs/specs/published-consumption-surfaces.md`,
`docs/specs/remote-client-removal.md`, plans 045 and 046.

## Highlights

- **`collect_installed_agents` answers the whole question in one call.** What
  this machine is running, its Agent BOM, its posture findings, its
  observations, its warnings — one pass, no internals. `collect_for_agent`
  does one agent; `CollectedAgent` is the result type. Discovering nothing
  returns an empty sequence, because "nothing is installed here" is an answer
  rather than a failure.

- **Each result carries that agent's own `config_root`.** This is the field
  that matters most and is easiest to miss: on a machine running two agent
  kinds, an argument-level root can be at most one kind's, so a consumer
  relativising the other kind's paths against it gets bare basenames with
  nothing raised — a partially-relativised document and no error. Relativise
  against `collected.config_root`.

- **Findings come back as themselves.** `PostureFinding`, `ObservationFinding`
  and `Standards` are exported, so findings arrive in OpenACA's vocabulary
  rather than some server's payload shape. The removed client converted them at
  collection time — `rule_id` to `finding_id`, `title` to `summary` — and that
  mapping belongs to whatever consumes the findings.

- **`validate_kind_selection` publishes the rules, not just the facts.** An
  unknown `--kind`, a `config_dir` without a kind, and a kind that refuses a
  root override are all rejected with the message OpenACA's own CLI shows. This
  is published because a consumer that cannot reach it does not merely lose an
  error message: an unknown kind collects nothing and looks like success, and a
  refused override reads a directory the caller never named. Both are
  indistinguishable from working.

- **Policy compilation moved below the command layer.**
  `compile_endpoint_policy` and `render_policy_report` are on the facade and
  raise `PolicyValidationError` / `PolicyEvaluationError` — domain errors, not
  Click exceptions. A programmatic caller no longer needs to know what Click is.

- **`ScannerUnavailable`** is the one failure the collection call expects, so
  `external_scanners` has a nameable error instead of a bare `Exception`.

- **`openaca.cli.main` is a supported import path.** A consumer can mount
  OpenACA's `scan`, `bom` and `policy` command objects into its own Click group
  and offer them under its own name, with no wrapper and no subprocess. Usage
  lines render the invoking program, so the commands read as native.

- **The hosted-service client is removed** — `tools/remote/`, its tests, the
  three MDM scripts whose only job was scheduling uploads,
  `docs/remote-deployment.md`, and `httpx`, which nothing imports any more.
  OpenACA now holds no credential, no API URL, no upload path, and no notion of
  an account or a tenant. It does not learn the machine's host name:
  `socket.gethostname()` left with the collector, and nothing else calls it.

## Install

`uv tool install openaca==0.6.0` or `pip install openaca==0.6.0`.

## Compatibility

Pre-V0 — no back-compat hedging.

- **`openaca remote` no longer exists.** `configure`, `status`, `sync endpoint`
  and `policy compile` under it are all gone, with no deprecation shim.
  **v0.5.0 is the last release carrying them** — pin it if you depend on the
  command, and move to the consumption surfaces above otherwise.

- **`scan endpoint` no longer suggests `sync to remote:`** as a next action.
  This is the one deliberate output change in the release; every other
  surviving command's output is byte-identical, including `scan endpoint
  --json`, `bom endpoint`, `policy compile`'s artifact, and all 16 commands'
  `--help`.

- **BOM schema version stays `0.5`.** No emitted structure changed: the only
  edits to `tools/bom.py` and `tools/graph_build.py` in this release are
  comments and docstrings. Recorded so the next release knows the check ran.

- **The overlay record schema is unchanged.**

- **ADR-0063** records the removal and supersedes ADR-0032, ADR-0050, ADR-0051
  and ADR-0061. It also amends ADR-0045: an agent's instance key still spans
  (asset, kind, agent id), but the asset half is now supplied by whatever
  consumes OpenACA rather than read from a registration envelope this project
  no longer has.

- **`build_graph` is dead production code.** Its only production caller was the
  removed client. It is kept for now because deleting it cascades into
  `tools/bom.py`'s schema-`0.4` branch, which stays live by another path
  (graphless `build_agent_bom`).
